# Fork: Windows SSH attachment

This branch adds an opt-in attachment to an existing remote DSH service. In an SSH host's DSH settings, enable **Reuse an existing remote DSH instance**, select Windows or macOS / Linux, then use the usual SSH username, password or private key, and verify the SSH host key. With Tailscale, enter the remote device's Tailscale address. This keeps the existing DSH service and its workspaces; it does not start or restart DSH.

For Windows, a blank log path uses `%USERPROFILE%\.dsh\remote-host-restart\dsh.log`; another path can be configured. For macOS / Linux, specify the log path. The log must contain the service's current loopback launch URL. The application reads that URL over the encrypted SSH connection and forwards its loopback port through SSH. It does not save the launch token as part of the host configuration. A stale log, stopped service, inaccessible log, or SSH forwarding disabled will prevent connection. The standard SSH bootstrap mode is unchanged. Service installation and lifecycle management are outside this change.

The `Fork Android APK` workflow runs SSH tests, builds the arm64 runtime with the current patches, and uploads the APK as an Actions artifact. To seed a pinned Termux proot package no longer in the current package index, the workflow downloads the official build artifact and verifies the package's SHA-256 before use. The fork APK uses a separate Android application ID so it can be installed beside upstream. Unless a persistent release signing key is configured, CI signs with a newly generated debug key; APKs from different runs cannot necessarily update one another. Reinstallation may remove this test app's local data. No claim is made about mobile background survival or network quality until tested on a phone.

The second test package uses a different application ID from the first test package because CI's temporary signing key cannot update that installation. SSH hosts use smaller initial and paged history windows, background list reads, and worker-isolate decoding of large mux frames and snapshots. Older history remains available by paging. These changes do not modify DSH on the Windows host or change Tailscale routing.
